# 交易内核（Rust）

> 量化策略实际运行的内核是 Rust。Swift 保留 UI、交易所连接与持久化。

## 1. 边界怎么划的

| 归属 | 内容 | 为什么 |
|---|---|---|
| **Rust**（`kernel/`） | 指标库、表达式 DSL（词法/语法/求值）、回测引擎（二值 + 连续敞口）、绩效指标、仓位计算、**实盘信号决策** | 确定性计算。正确性与可复现性是第一位的，且这里是「回测与实盘必须一致」的地方 |
| **Swift**（`Sources/`） | SwiftUI 界面、菜单栏、OKX REST/WebSocket、okx CLI 桥、配置与台账持久化、异步编排 | 平台 I/O。URLSession、async/await 和 AppKit 在这里是正确的工具，搬进 Rust 只会重复造轮子 |

**没有把网络和下单搬进 Rust**，因为那部分的难点是并发与平台集成，不是计算，Swift 做得更好。

### 1.1 交易所是注入进来的，不是写死的

Swift 那一侧还有一条边界：`ExchangeVenue`。它是交易 infra 的**端口**，
`StrategyRunner` 只认这个协议，全文没有出现过 OKX。

```
StrategyRunner ──▶ ExchangeVenue（协议）──▶ OKXVenue ──▶ OKXRESTClient + TradeBridge
                                        └▶ 换任何交易所：新增一个同级 conformance
```

接协议时刻意做窄：只放交易循环真正需要的东西（行情、下单、订单状态、成交、仓位、
账户）。订单簿、费率档位这类各家差异极大的能力留在具体适配器上，新交易所不必去实现
一个永远不会被问到的接口。

唯一的可选能力是 `alternativeSeries`（资金费率、持仓量、多空比）——协议扩展给了
默认空实现。这不是静默降级：缺失的序列对齐成 NaN，而 NaN 在内核里一律是**未知**，
依赖未知的信号永不触发。**没有这些数据的交易所会拒绝交易，而不是盲目交易。**

换交易所要改的只有 `AppState.venue` 那一行。

## 2. 这次重构真正买到了什么

不是性能。是**消除了一个结构性风险**。

重构前：
- `BacktestEngine.desiredDirection` —— 回测的信号判定
- `StrategyRunner.decide` —— 实盘的信号判定

两个独立的 Swift 函数，靠一句注释「Mirrors BacktestEngine.desiredDirection」约束它们一致。
任何一边改动而另一边忘了改，结果就是**实盘交易的规则与你回测过的规则不同**，
而且不会有任何报错 —— 这是量化系统里最贵的一类 bug。

重构后：只有一个 `decide::desired_direction`，回测在第 i 根调用它，实盘在最新已确认 K 线上调用它。
**它们不可能不一致，因为只有一个。**

[KernelGoldenTests.swift](../Tests/MayStockKitTests/KernelGoldenTests.swift)
里的 `theLiveDecisionMatchesTheBacktestBarForBar` 把这条性质钉成了测试：
逐根前推调用实盘决策，必须复现向量化回测得到的同一串信号。

## 3. FFI 形状

```c
MSStrategy *ms_strategy_compile(const char *manifest_json, const char *known_series_json, char **err);
char       *ms_strategy_decide (const MSStrategy *, const MSCandle *, size_t, int32_t current, int64_t held,
                                const char *ext, double equity, double held_base,
                                double day_start_equity, double leverage_cap, char **err);
char       *ms_backtest_run    (const MSStrategy *, const MSCandle *, size_t, const char *config_json, char **err);
void        ms_strategy_free(MSStrategy *);
void        ms_string_free(char *);
```

- **K 线走裸 `#[repr(C)]` 数组**：6000 根约 330 KB，每个 tick 序列化成 JSON 的开销比它喂的计算还大。
  `kernel/src/candle.rs` 里有一条单元测试断言 `size_of::<Candle>() == 56`，
  布局改了就编译期失败，而不是把价格当成时间戳解释。
- **配置与结果走 JSON**：它们小、形状会随功能变，手写一份 `BacktestResult` 的 C 结构体
  只会变成永久的布局 bug 来源。
- **编译后的策略是不透明句柄**：解析清单不免费，而实盘运行器每 20 秒就要用一次。
- **每个入口都包了 `catch_unwind`**：panic 跨 FFI 边界是未定义行为，
  而这个库被加载进持有交易所会话的进程里 —— 必须以错误字符串失败，不能以崩溃失败。

## 4. 编译时就拒绝，而不是第一根 K 线上才炸

`CompiledStrategy::compile` 会拿 4 根假 K 线把每条表达式**真的跑一遍**。
这样未知函数、参数个数不对、周期非法都在导入时被拒绝。

刻意没有再写一张校验表：第二张表就是第二个需要与求值器保持同步的东西，
而它们不同步的那个场景，恰恰就是「策略导入时干干净净，然后在持仓状态下失败」。

## 3.1 `decide` 返回的是完整下单计划，不只是方向

```json
{ "target": -1, "targetExposure": -0.333, "targetBaseQuantity": -0.2051,
  "baseDelta": -0.0886, "shouldTrade": true, "haltDailyLoss": false,
  "reason": "敞口 -0.193 → -0.333" }
```

**仓位计算、再平衡阈值、日内亏损熔断三样都在内核里**，Swift 只负责把
`baseDelta` 发出去。运行器里不再出现任何 `sizing.mode` / `maxDailyLossPct` /
`rebalanceThreshold`。

之前这三样在 Swift 各有一份，而且**已经漂移了**：Swift 的 `riskPerTrade` 只认
百分比止损，遇到只声明 ATR 止损的清单会回退到满仓 —— 同一份清单，回测每笔冒
1% 风险，实盘押上全部预算。

`kernel/src/sizing.rs` 是这次抽出来的共用模块，回测的 `open_position` 和实盘的
`decide_live` 调的是同一个 `target_notional` 与 `stop_distance`。
[LiveSizingParityTests](../Tests/MayStockKitTests/KernelGoldenTests.swift)
把这条性质钉死：同一根 K 线、同样的资金，实盘计划开出的名义额必须等于回测开出的。

**保护性离场随单挂到交易所**：计划里的 `stopPrice` / `takeProfitPrice` 作为
`--slTriggerPx` / `--tpTriggerPx` 附在入场单上，由交易所 24 小时执行。
不用 20 秒轮询 —— 轮询会睡过止损存在的那根插针，应用关掉时更是完全不设防。
触发后按市价成交（`--slOrdPx -1`）：限价离场可能在它本要躲开的行情里一直挂着不成交。

**冷却与日内熔断也在内核**：`can_enter` 回测和实盘共用；熔断只锁当天，
UTC 日切换时由运行器清空 —— 回测正是这么做的，实盘若永久锁死，
回测收益里就含有实盘永远拿不到的次日交易。

一个刻意的设计：**取不到仓位大小时，`target` 仍然报出信号方向**，只是
`shouldTrade` 为 false。把它报成「空仓」会让调用方以为策略没有观点，
而事实是它有观点但执行不了 —— 状态栏要显示的正是后者。

**时间栅栏（`risk.maxHoldBars`）**：止损和止盈限制价格能走到哪里，却没有限制
仓位能躺多久。一笔论点已经不成立、但既没打到止损也没打到止盈的交易，会无限期
占着资金。这是 Triple Barrier 的第三条边，同样只有 `desired_direction` 一份实现。

它**压过包括反手在内的所有信号**：让反手绕过时间上限，等于在它最该生效的震荡行情
里让它形同虚设。到期就平，要不要再进场是下一根 K 线的新决定，照样受冷却约束。
编译期会拒绝 `maxHoldBars < minHoldBars` —— 那条仓位既不许平又必须平。

> 顺带修掉一个隐藏很久的 bug：`StrategyPositionState` 记录的开仓时刻从不清零，
> 于是「持仓多少根」算的是**策略有史以来第一笔成交**至今。`minHoldBars` 因此几乎
> 从不生效（无害），但时间栅栏会在开仓瞬间就把仓位平掉。现在它随平仓清空、
> 随反手重置。

## 3.2 交易所会做我们没让它做的事

内核算得再对，也架不住仓位在它背后被改掉。这几件事只可能在 Swift 侧处理，
但每一件处理错了都会让「内核以为的仓位」和「真实仓位」分叉。

**下单超时不是下单失败。** 请求可能已经到了交易所并成交。当成失败会把一笔真实
仓位留在台账之外、且策略已停无人看管。所以未确认的订单会被记下来，下一个 tick
开头先向交易所核实（早于任何新决策 —— 拿着账上没有的仓位去定仓会让错误复利）。
只有「交易所根本没这单」才允许重试；部分成交后被撤的仍算成交。

**交易所侧的平仓要补记。** 我们特意把止损附在入场单上让交易所 24 小时执行，
可它触发时成交带的是交易所自己的单号，不是我们的 `clOrdId` —— `ingestFills`
会跳过它，台账继续以为仓位还在。强平、ADL、手工平仓长得一模一样。
**幽灵仓位比不准的仓位更糟**：下一次定仓会按不存在的币去算，平仓会去卖不存在的东西。

对账规则，每条都是刻意的：

| 规则 | 为什么 |
|---|---|
| 只对永续 | 现货余额混着用户本来就有的币，差额不能证明任何事；永续是逐合约上报的，也正是会被强平的那个 |
| 查询失败绝不当成「已平仓」 | 否则每次网络抖动都会记一笔强平 |
| 要两次一致的读数 | 刚成交的单不会同时出现在成交和仓位两个接口上 |
| **只吸收减少方向** | 多出来的是别人的单（手工、别的机器人），并进来会让策略去平掉用户故意开的仓 |
| 优先领取交易所自己的成交记录 | 止损成交在止损价，不在一分钟后的标记价；真成交还带着真手续费 |
| 同一合约多策略时熔断，不按比例分摊 | 强平打的是净腿，拆不出是谁的钱亏了 —— 按比例分是编故事 |
| 补记后记入退出 bar | 被交易所平掉也是一次退出，冷却照样算，和回测一致 |

**移动止损：内核算价位，Swift 只负责搬。** OKX 自己有移动止损单
（`algo trail --callbackRatio`），逐笔跟，比我们紧。**没有用它**——它按每一笔成交跟，
回测按 K 线极值跟，把活交给一个行为不同的机制，等于跑的策略不是测过的那个策略。
内核每根 K 线报出 `trailingStopPrice`（**包括不交易的那些 bar**，因为价位会动而仓位不动），
Swift 用 `algo amend` 原地改价。用 amend 不用撤单重挂：撤掉的那一刻仓位是裸的，
而那正是快速行情吃掉你的窗口。两根 bar 之间交易所守的是上一档价位，所以仓位从不裸奔，
只是按它被测试过的节奏收紧。

止损的**地板**是开仓时那道固定止损，其 ATR 取的是**下单决策那根 bar**（成交前一根）——
和回测定仓用的是同一根。取当前 bar 会让地板随波动率漂移，而一道会随行情转平而放宽的止损
不叫止损。

**交易所拒绝附加止损时不放弃这笔交易。** OKX 会因为触发价离标记价太近或太远
而拒单。因为**保险**不被接受就放弃**信号**是错的取舍：改发裸单，然后由运行器在
tick 上盯这个价位，并明确告诉用户「App 关闭期间不受保护」。
前提是能区分「交易所明确拒绝」和「结果未知」——`TradeError.exchangeRejection`
只在响应里带着非零 OKX 错误码时才返回值；超时和 socket 错误一律算未知，走上面的核实流程。

## 3.3 回过头量一量：实盘到底跟上回测没有

回测说 +67%，实盘跑成 −3%，这件事越早变成一个屏幕上的数字越好。
`kernel/src/reconcile.rs` 回答两个问题，都从数据来，不从假设来。

**实测滑点。** 回测按 `slippageBps` 收费，那个数是人拍的。每一笔真实成交拿去和
**它落在的那根 bar 的 open** 比——正是回测建模的东西（bar *i* 收盘出信号，
bar *i+1* 开盘成交 + 滑点），所以算出来的数可以直接和清单里的假设比，而不只是「差不多」。

几个刻意的选择：取**中位数**而不是均值（一笔打在插针上的成交不该定下未来所有回测的成本），
但**同时报 P90**（只看中位数的成本模型，会在最需要的时候准备不足）；
**保留占了便宜的成交**（市价单偶尔有价格改善，扔掉它们会让估计系统性偏高）；
成交落在 K 线窗口之外就**不计数**，而不是拿旁边那根凑。样本少于 10 笔不给建议值——
拿三笔成交去改成本模型，只是把一个猜测换成一个更自信的猜测。

**净值对照。** 把回测净值按时间对齐到实盘净值上比。对齐是**阶梯式**的
（每个实盘采样点配最近一个不晚于它的回测点），不做插值——插值等于编造模拟从未报过的净值，
而两根 bar 之间恰恰是回测没有意见的地方。超出回测窗口的实盘采样点**直接丢弃**，
否则它们全会配到最后一个回测值、被当成回测走平，读起来就成了实盘跑赢。

报三个数，各答一个不同的问题：

| 指标 | 回答 |
|---|---|
| 收益差 | 差多少 |
| 跟踪误差 | 每一段的差异有多不稳定 |
| 形态相关性 | **是同一个策略成本更贵，还是压根在做另一件事** |

相关性在曲线不够波动时报 **null 而不是 0**——0 读起来是「不相关」，实际是「无定义」。
判据是相对下限而不是「方差 > 0」：一条按固定利率复利的曲线，收益方差是 1e-33 而不是 0，
除下去会得到一个完全由舍入误差构成、看起来却很自信的数。

这两件事本可以在 Swift 里做。放在内核，是因为它们是对市场数据的确定性计算，
**答案不该取决于是谁在问**。

这两条同时要求实盘净值必须是**按策略**的：账户净值把所有策略混在一起，
回答不了「这一个策略跟上它自己的测试没有」。于是 runner 每分钟给每个有配额的策略
单独采一个净值点（停掉的也采——停掉的策略仓位照样在动，曲线缺一段会把跨越缺口的收益算错）。

## 3.4 三道闸门：数据、订单、组合

调研顶尖量化框架后补的三层防护。共同点是：**它们保护的不是策略的判断，而是策略判断错时的后果**。

**行情质量（`kernel/src/quality.rs`）。** 回测拿到的是干净连续的数组，实盘拿到的是交易所
当时返回的东西——可能是一根陈旧的 bar、一个本该有 bar 的洞、或者同一根 bar 两次。
下游每个指标都会从中算出一个数，而那个数看起来和真的一模一样。
所以序列在信号之前先被检查，**数据不干净时拒绝决策**——注意是拒绝决策，不是给出空仓目标，
否则行情打个嗝就会把仓位平掉。

阈值都不是零：容忍 2% 以内的缺口（稀薄市场里交易所确实会偶尔丢 bar，为一个洞停一整天
是另一种失败），落后 2.5 根才算陈旧（bar 要等下一根开出来才确认，健康的行情源本来就落后
一整根）。回测传 `now_ms = None`：历史数据按定义就是陈旧的，这条性质在那里没有意义。

**下单前风控（`kernel/src/guard.rs`）。** 学 NautilusTrader 的 RiskEngine。定仓本来就有预算和
杠杆两道上限，所以正常情况下这里永远不触发——**这正是重点**。它拦的是不正常的情况：
止损距离算成了一个舍入误差、标记价读到一根坏 tick、清单被改成 `fixedQuote: 1000000`。
每一种都会产出一个定仓函数乐于返回的数字。

三条规则值得说明：**非有限的下单量在任何状态下都拦**（那不是一笔大单，那是算错了）；
**减仓永远不受尺寸上限约束**（拒绝平仓，正是保护性限额变成它本要防止的那个东西的方式）；
熔断跳进的是 `Reducing` 而不是 `Halted`——**停摆的引擎平不掉那个让它停摆的仓位**。

**组合级保护。** 学 Freqtrade 的 MaxDrawdown 与 StoplossGuard。
单策略日内熔断看不见四个策略各亏 4%，而那正是该收手的一天。连续止损保护则是因为：
策略可能完全按设计工作、每一次止损都触发得对，账户就这么一次一次正确的止损里流干。

## 3.5 这个回测结果里有多少是「看得多」

`kernel/src/overfit.rs`。搜一千组参数，最好的那组夏普一定好看，无论其中有没有一组真有边际。

- **Deflated Sharpe**：观察到的夏普在「无技能」原假设下有多大可能，同时修正试了多少次
  和收益分布的偏度峰度。偏度峰度不是装饰：夏普估计量自身的标准误就取决于它们，
  而**小步稳赚、偶尔巨亏**恰好是朴素优化器最容易走进去的形状。
- **PBO（CSCV）**：把序列切成连续块（不打乱——打乱会破坏交易策略收益的自相关性），
  穷举所有对半切分，看样本内冠军在样本外落到中位数以下的比例。
  它验的是**选择过程本身**，所以能抓到「每个单独回测都没问题、但这次搜索换一段数据
  就会选出另一个冠军」。

两个都要，因为它们答的不是同一个问题：DSR 可能放行一个边际真实但微弱的策略；
PBO 能抓到搜索本身是坏的，哪怕每个回测单看都体面。

两处刻意的处理：并列名次取**中位排名**（把并列判成赢，等于说冠军赢过了它其实只是打平的对手，
而近乎相同的候选正是过拟合搜索的产物）；相关性/显著性在曲线不波动时报 **null 而不是 0**。

还有一条值得记下来，免得以后有人来「修」：标准误是**双向**加宽区间的。
观察到的夏普已经低于门槛时，估计越不可靠，我们对「它低于门槛」这件事也越不确定，
概率是往 0.5 走而不是往 0 走。这不是 bug，测试里专门钉了一条。

`Statistics.expectedMaxSharpeUnderNull` 的 Swift 实现已删除，优化器改调内核。

## 3.6 参数寻优：整轮在内核里跑完

原来每个网格点都要：Swift 重新编码清单 → `ms_strategy_compile` **重新解析每一条表达式** →
跑回测 → 把六千个净值点和全部成交序列化成 JSON → Swift 解析回来 → **只读六个数**。
五千次，串行，单核。

三个观察让它塌缩掉：

1. **参数值不改变解析后的表达式。** AST 只取决于源文本，网格点之间只有 `params` 不同。
   所以一个候选是「克隆编译好的策略 + 换一张 map」，不需要词法、语法、校验。
2. **寻优只需要 metrics。** 曲线和成交列表正是让结果序列化变贵的东西，而寻优两个都不看。
3. **网格点彼此独立。** 除了只读的 K 线，没有共享状态。

剩下的就是一个对克隆结构体的并行循环，和最后一份很小的 JSON。

实测（1000 组参数 × 6000 根 K 线，M 系列）：

| 路径 | 每候选耗时 |
|---|---|
| 旧：重新解析 + 全量结果 JSON | 0.400 ms |
| 新：单线程 | 0.148 ms |
| 新：自动线程数 | **0.042 ms** |

**9.5×**，而且这还没算旧路径在 Swift 侧额外付的 JSON 编解码。

两处刻意的设计：结果**按网格顺序回填**（用一个 slot 数组而不是追加），
因为**输出取决于线程调度的回测不可复现，而不可复现的回测不算证据**；
交叉验证的收益序列走**第二遍重跑**而不是第一遍全存 —— 重跑二十几次回测，
比在内存里攥着五千条净值曲线便宜得多（6000 点 × 5000 组 = 四分之一 GB 的 f64，
存下来只为了扔掉）。

`with_params` 会**按清单声明的 min/max 夹取**：调用方不能靠传一个范围外的数
来扩大参数的定义域。求值不了的网格点（周期为 0、NaN）被跳过并**计数上报** ——
跳掉了大半个网格的搜索什么也没找到，无论冠军长什么样。

## 3.7 回测的完整性

- **回测报告现在说明它跑在什么样的数据上。** 跨越缺口的 60 根回看窗口，覆盖的市场时间
  多于 60 根。实盘会直接拒绝这样的序列；回测无法事后拒绝，所以它如实报告。
- **回测应用与实盘同一套下单前限额。** 只有定仓 bug 才会触到它们，而这正是 bug 该浮现的地方：
  一份悄悄模拟了实盘会拒绝的订单的回测，是不能拿去交易的回测。
  **但交易状态机不套用** —— 组合回撤刹车是实盘风控，不是策略的规则，
  把它折进模拟等于测了另一个策略。

## 3.8 一个咬了我两次的坑，已变成一条测试

SwiftPM 跑不了 cargo，所以 `Scripts/build-kernel.sh` 负责暂存静态库，
`swift build` 链接暂存的那一份。改完 Rust 直接 `swift test`，**测的是上一版内核** ——
而且是无声的：Rust 里新加的字段在 Swift 侧解码成 nil，症状看起来像逻辑 bug。

现在有一条测试比较暂存库和最新 `.rs` 的修改时间，失败时直接说「先跑 build-kernel.sh」。
一条会说话的失败，比构建脚本里的一句注释值钱。

## 3.9 Walk-forward 的 purge 与 embargo

样本外那一段必须自带预热，指标才能像实盘一样起步 —— 这意味着**分割点之前那些 bar
喂养了测试期的第一批信号**。用同一批 bar 去拟合参数，就是教科书上的泄漏：
训练集里含有测试集依赖的观测。

所以拟合窗口在它们之前 `warmup` 根就停下（**purge**），再往前留 `embargo` 根
（默认每折 1%，López de Prado 的做法）。purge 只删掉测试**机械上**需要的东西，
而价格是序列相关的，边界两侧描述的几乎是同一个市场状态 ——
一直拟合到边缘，就是拟合到测试集本身。

协议参数**写进报告**而不是靠默契：折数、样本内占比、purge 根数、embargo 根数。
一份没写下这些的 walk-forward 没法和另一份比较，而它们的差别，
正是「真正的样本外测试」和「延迟了一点的样本内测试」之间的差别。

## 3.10 有效独立注数：两个 0.95 相关的策略是一注加倍

给每个策略单独配资，不等于在策略之间做了分散。BTC 和 ETH 上的两个趋势跟踪，
在崩盘时会一起走 —— 而那正是分散本该起作用的时刻。于是这个组合是**一个双倍大小的仓位**，
而任何单策略回测都看不出这一点。

`reconcile::diversification` 算全部两两相关性和**有效独立注数** `N² / ΣΣ ρᵢⱼ`：
N 个完全相同的策略，这个数是 1。

一处刻意的处理：**只要有一对相关性无法定义，整个有效注数就报 null**。
把未定义当成 0 相关，等于把一条走平的策略算成免费的分散来源。

## 3.11 换个成交顺序会怎样

回测报出一个最大回撤。那个数字是**分布里的一次抽样** —— 同样这些交易换个顺序，
最难受的那一段就不一样，而它们碰巧到来的顺序，对它们下次到来的顺序没有任何信息量。

后果很直接：观察到 31%、重采样 95% 分位 44%，那么定仓和组合熔断该按 **44%** 建。
回测报出的那个是这个策略能对账户做的事情里**乐观的那一尾**。

`kernel/src/resample.rs` 提供两种方法，因为它们回答不同的问题：

- **shuffle** 保留每一笔交易只改顺序 —— 问「回撤里有多少是顺序造成的」。
  每笔只出现一次，所以复利可交换，**终点不会动，动的只有路径**。
- **block bootstrap** 有放回地抽连续片段 —— 同样的问题，但保留聚簇。
  连亏不是独立抽样，把它们打散的方法会**低估它本要度量的那条尾巴**。

块长是**建模选择而不是自由参数**：在一段五赢五输交替的数据上，块长 10 无论从哪切
都恰好含五赢五输，尾巴被抹平；块长 5 才能把连亏叠起来。这条专门写了一个测试记着。

随机数用固定种子的 LCG，不是系统随机源：**每次算出来都不一样的风险数字没法被质疑，
而没法被质疑的数字不能被信任**。取模用拒绝采样而不是直接 `%` —— 偏差很小，但省掉它是免费的。

爆仓的序列在 0 停住，不继续复利成负权益 —— 那会模拟一笔交易所早就强平掉的负债。

> 这一条本身就抓到过一个 bug。第一版接线把 `returnPct` 当成小数喂进去，
> 于是一笔 −20% 的交易变成 `1 + (−20)`，报出「回撤 100%」。
> 数字荒谬到一眼就能看出来 —— 而根因是内核那条注释写着「as a fraction」，
> 值却乘了 100。注释已改，Swift 侧也加了 `returnFraction` 让单位不再靠记忆。

## 3.12 高周期过滤器与对齐

`AlternativeSeriesSpec.bar` 现在可以粗于策略自身的周期 —— 小时级策略上挂一个日线趋势闸门。
这需要先修对齐规则。

K 线的时间戳是**开盘时间**。原来的对齐只比较开盘时间，同周期下恰好是对的
（决策发生在 bar 收盘，那一根的收盘价此刻已知），但一旦允许粗周期，
它会把一根还有 23 小时才收的日线的**收盘价**交给凌晨一点的小时 bar —— 23 小时的未来函数，
正是高周期文献里叫 repainting 的那个失败。

现在的规则是「到本 bar 收盘时它自己是否已经确定」，而两类数据在边界上**真的不同**：

| 类型 | 规则 | 为什么 |
|---|---|---|
| 按 bar 度量（另一标的的收盘） | `obs.ts + obs周期 <= 本bar收盘` | bar *i* 自己的收盘价在 bar *i* 收盘时可用，这是执行模型本身 |
| 时点发布（资金费结算） | `obs.ts < 本bar收盘`（严格） | 落在决策同一刻的数据，假设你已经握有它是乐观读法，而乐观读法正是让回测撒谎的东西 |

`candleSeconds` **没有默认值**：答案取决于它，一个没想清楚自己何时决策的调用方
不该靠碰巧拿到正确的对齐。

顺带修正了一条更早的测试所编码的规则：它断言「发布于 bar 开盘之后的值就是未来函数」。
保证的是**决策时刻**，而决策在 bar 的收盘。发布在 bar *i* 之内的数据，
bar *i* 的信号确实握有它，拒绝它等于模拟一个实盘并不存在的滞后。
真正不能碰的是发布于该收盘**之后**的数据 —— 现在测的是这一条。

## 3.13 连续敞口引擎缺的两道闸

回测两条引擎：二值（进出场）和连续（按比例持仓）。风控条款一直只加在二值那条上，
而**线上两个 volscaled 策略正是连续型**。

**日内熔断。** `decide_live` 在分支到敞口之前就检查 `maxDailyLossPct`，
所以**实盘对连续策略是执行熔断的**；`continuous.rs` 完全没有这段。
一份继续交易的模拟，会把运行器本该坐视不动的那些天的收益也算进去。
熔断只锁当天，UTC 日切清除 —— 否则回测会拒绝运行器明天照常会做的交易。

**强平。** `liquidations: 0` 是写死的。一个 5 倍杠杆的连续仓位，
可以在模拟里一路扛过 40% 的下跌到回测结束 —— 交易所绝不会允许。
连续仓位每次再平衡都在变大小，所以强平价按**当前持仓**重算，而不是在开仓时定死。
强平价的算法抽成 `liquidation_buffer`，两条引擎共用一份定义。

## 3.14 心跳：进程活着，但循环停了

`tickStallTimeout` 只能救活卡住的**单次** tick。整个 loop 死掉、app 被杀、
笔记本睡过去之后，没有任何信号 —— 什么都不报错，面板继续显示它最后拿到的数字，
账户只是不再有人管。这正是运维文献里 dead man's switch 要解决的那类失败：
**「进程还在，但它已经不做那件事了」**。

所以引擎主动说「我还在干活」，而**这个信号的缺席**才是警报。落盘而不只是留在内存里，
因为要回答的问题是「我没看着的时候它在跑吗」，而内存里的值在重启之后回答不了。
写入有节流（30 秒），tick 频率远高于这件事需要的分辨率，而每次写都是交易循环里的磁盘 I/O。

心跳告警**盖过**组合保护的横幅：暂停是一个决定，而循环死了是一个没人管的仓位。

## 3.15 心跳报的第一个真警报：子进程把 tick 永久挂住

心跳上线后报出的第一件事不是误报，是真的：**交易循环 143 分钟没有完成一次轮询**。
根因在 `TradeBridge` 的子进程看门狗里，一行看上去无害的提前返回：

```swift
DispatchQueue.global().asyncAfter(deadline: .now() + timeout) {
    guard process.isRunning else { return }   // ← 没有 resume continuation
    ...
}
```

`okx` CLI 是个 node 程序，它会**留下一个继承了 stdout 的后台子进程**（版本检查之类）。
于是父进程立刻退出，管道却还开着：`readDataToEndOfFile` 永远读不到 EOF，
15 秒后看门狗醒来一看 `isRunning == false`，认定「没有要杀的东西」就直接返回了 ——
**continuation 再也没有人 resume**。调用方就此永久挂起。

在交易循环里，这意味着 tick 再也没有回来。没有报错、没有退出，面板照旧显示它最后
拿到的数字，只是仓位从此无人管理。这就是 3.14 那个死人开关存在的全部理由，
而它确实抓住了。

两条修法，都收拢进 `Subprocess`（`okx` 桥和外部脚本引擎此前各写了一份，
**同一个 bug 也各写了一份**）：

- **超时无条件 resume**。还活着的孩子照杀，已经走掉的照报。进程死没死，
  跟「调用方该不该被唤醒」本来就是两件事。
- **改用 readability handler 排空管道，不再阻塞读**。原来每个调用要占住两个线程等
  EOF；一个反复卡住的 CLI 会把全局队列的线程池耗光，而看门狗自己就排在那个池子上 ——
  修好第一条也会被第二条重新拖死。

还有一条结构性的：**循环不再 `await` 单次 tick**。

```swift
runner.beginTick()          // 发射不管落地
try? await Task.sleep(...)  // 循环自己掐表
```

原来 `await runner.tick()` 让整个引擎的存活挂在每一次 tick 都必须返回上，
这个假设一旦破掉就是永久性的。现在超过 `tickStallTimeout` 的 tick 会被
**取消并替换**：取消而不是遗忘，因为它万一真的返回了，握着的是几分钟前的价格、
仓位和 K 线 —— `submit` 与逐策略循环都会在下单前先看一眼 `Task.isCancelled`。
被放弃的 tick 也**不上报心跳**：拿一次没干活的轮询去报平安，正好盖住这套机制要抓的东西。

## 3.16 覆盖率量的是密度，不是两端距离

3.15 那次停摆还留了后半截没补。`EquityChange` 的文档说它「明确交代这个窗口里有多少
是真实采样撑起来的」，但 `coveredSeconds` 实际算的是：

```swift
coveredSeconds: endTs.timeIntervalSince(start.ts)   // ← 两端距离
```

**首尾横跨一天的曲线就是横跨一天，中间缺多少都一样。** 于是那天引擎死了 72%，
面板照样认为 1d 窗口 100% 覆盖，`isComplete` 为真，一个自信的收益率就这么打了出来 ——
它是拿一天里零散的三个半小时算出来的。

现在按**采样密度**算：逐对累加 `min(间隔, 容忍度)`，超出容忍度的部分是窟窿，不计入。
容忍度刻意取 300 秒，和心跳判定「引擎没在跑」用的是同一个数 —— 横幅和覆盖率
不该对「这段时间算不算被观测过」有两种说法。超过 `fineHorizon` 的部分曲线本来就被
抽稀到 `coarseInterval`，那一段用 `coarseInterval * 2`，否则会把我们自己的压缩报成停摆。

`spannedSeconds` 单独留着，因为两者要分开回答两个问题，而 UI 需要这个差别：

| | 含义 | 面板 |
|---|---|---|
| 跨度不足 | app 刚装上，还没记那么久 | 灰色「记录 20 分钟」 |
| 跨满但有洞（`hasGaps`） | 引擎当时没在跑 | **红色「缺 6 小时」** |

拿真实数据回测这条改动，当天曲线的 1h 窗口从「100% 覆盖、照常出数」变成
「44.8% 覆盖、缺 0.6 小时」。抖动不算窟窿：实际采样是 60–120 秒一个点，
遇上慢的 CLI 调用还会更长，容忍度按 300 秒给，不会每小时喊一次狼来了。

## 4.1 迁移已完成，Swift 侧没有第二份实现

已删除：`Indicators.swift`、`StrategyExpression.swift`、`StrategyEvaluator.swift`、

## 5. 验证：从差分改成黄金数据

删掉任何 Swift 计算代码之前，先证明两边算出同一个结果。18 个差分测试当时全绿：

- 28 条指标/表达式逐根比对（含 Kleene 三值逻辑的判定用例）
- 8 组完整回测**逐笔**比对：均线交叉、止损+止盈同根、移动止损、ATR 风险定仓、
  日内熔断、冷却与最短持仓、永续做空+杠杆、连续敞口波动率目标
- 每笔比方向、成交价、数量、净盈亏、持仓根数、离场原因
- 再比总权益、净值曲线长度、夏普、索提诺、回撤、胜率、期望、费用、暴露度
- 容差 1e-9（指标）/ 1e-6（金额），只留浮点累积误差的余地

Swift 引擎删除后，差分测试失去了对照物，于是改成
[KernelGoldenTests.swift](../Tests/MayStockKitTests/KernelGoldenTests.swift)：
把当时两边一致的那组数值冻结成黄金值（8 个场景 × 成交数/终值/收益/回撤/胜率/手续费）。
之后任何改动内核的编辑，只要挪动了一笔成交、一个成交价或一项指标，就必须**显式**改这些数字 ——
这正是无声数值漂移需要的那个复核时刻。重新生成用
`MAYSTOCK_PRINT_GOLDENS=1 swift test --filter KernelGolden`。

**移植过程中真的被抓到四个差异**（都已修）：

1. `wma` 的 `x[i - period + 1 + k]` —— Swift 用有符号 `Int` 算中间值没问题，
   Rust 的 `usize` 在 `i - period` 这一步就下溢 panic。
2. 内核最初只在编译期检查标识符，未知函数/非法周期要到求值时才报错，
   比 Swift 宽松。用第 4 节的试跑修掉了。
3. 那个试跑一开始用空的外部序列表，于是合法引用 `funding_rate` 的清单
   会被自己的探针判成「未知变量」。改成把已声明的序列填进探针。
4. 现货清单声明做空时，内核的通用拒绝信息盖掉了 Swift 更精确的
   `shortingRequiresSwap`。把市场策略检查移到内核编译之前。
